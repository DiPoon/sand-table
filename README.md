# sandtable

> 대전략겜 동기화 깨지는 걸 서버 권위로 하면 해결할 수 있지 않을까?

서버 권위형(server-authoritative) 그랜드 스트래티지 시뮬레이션입니다. 시뮬레이션은 서버만 하고, 클라이언트는 명령(의도)을 보내고 서버가 보내 준 상태를 그리기만 합니다. 클라이언트끼리 같은 결과를 따로 계산하지 않으니 서로 어긋날(디싱크) 일이 없습니다.

서버 시뮬레이션은 결정론적입니다. 같은 데이터 + 같은 시드 + 같은 명령이면 CPU가 달라도 같은 상태 해시가 나오므로, 명령 로그만으로 어느 시점이든 재생하고 검증할 수 있습니다.

## 지금 되는 것

- **서버 (Go)**
  - 프로빈스 그래프 위의 이동과 공격, 전투(병력·조직력, 전투 폭, 예비대), 후퇴, 점령, 보급, 전장의 안개
  - 틱 루프, 배속·일시정지, 로비
  - 명령 로그·해시·스냅샷을 이용한 재시작 복구와 리플레이 검증
- **웹 클라이언트 (TypeScript, Canvas 2D)**
  - 프로빈스 좌표로 자동 계산한 Voronoi 지도와 사단 카운터
  - 마우스로 선택·이동·공격
  - 접속 화면과 로비, 끊기면 자동 재접속
- **프로토콜**: WebSocket 위의 Protobuf. 접속하면 스냅샷을 한 번 받고, 이후 틱마다 달라진 것만 델타로 받습니다.

샘플 맵은 프로빈스 16개, 진영 2개입니다. 생산·증원, 외교, 해·공군, AI, 승리 조건은 아직 없습니다.

## 실행

필요한 것: Go 1.26.5 이상, Node.js 22.12 이상과 npm.

```sh
make build                 # 웹 클라이언트(client/dist)와 서버 실행 파일(bin/)
cd server
../bin/sandtable-server    # http://127.0.0.1:8080
```

브라우저로 <http://127.0.0.1:8080>에 접속해 이름과 진영을 고르면 참가합니다. 탭 두 개로 두 진영을 잡을 수 있고, 먼저 들어온 쪽(호스트)이 대기실에서 시작합니다.

| 조작 | 동작 |
|---|---|
| 왼쪽 클릭 | 자기 사단 선택 (Shift: 추가/해제) |
| 오른쪽 클릭 | 선택한 사단을 그 프로빈스로 이동/공격 |
| 드래그, 휠 | 지도 이동, 확대/축소 |
| `Space`, `1`~`5`, `Esc` | 일시정지/재개, 배속(호스트만), 선택 해제 |

테스트:

```sh
make test                  # 서버: 결정론, 규칙, 영속성, end-to-end
cd client && npm test      # 클라이언트: 스냅샷/델타 적용, 좌표 계산, 재접속
```

터미널 클라이언트, 리플레이 검증, 개발 서버, 브라우저 종단 테스트는 [docs/README.md](docs/README.md#실행)에 있습니다.

## 원칙

- **클린룸.** 특정 상용 게임의 코드·에셋·고유 명칭·맵 데이터를 쓰지 않습니다. 시스템은 장르 관례를 따르고, 맵·수치·명칭 같은 콘텐츠는 직접 만듭니다.
- **데이터 주도.** 프로빈스, 유닛 타입, 전투 수치는 코드가 아니라 [`data/`](data/)의 YAML에서 읽습니다.
